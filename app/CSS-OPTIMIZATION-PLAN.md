Аудит `app/assets/css` (11 файлов, 2570 строк, 273 уникальных селектора) и того
кода в `assets/js`, который эту вёрстку порождает.

**Главный вывод: CSS не «зарос».** Дубликатов почти нет (два одинаковых блока
деклараций на весь проект), токены дисциплинированы, `!important` только там,

а не обход каскада. Долг накопился точечно, в пяти местах, и он измерим.

## A. Рендер: 39 слоёв размытия поверх плоского фона — **главный пункт**

`.widget` несёт `backdrop-filter: blur(256px)`, `.chips` —
`blur(calc(256 * var(--u)))`, что при `--u-scale: 1.3` даёт радиус ≈410px.
На KPI Library это 20 карточек + 19 треков чипов = **39 композитных слоёв**,
каждый заставляет компоситор считать гауссово размытие огромного радиуса.

Но размывать там нечего:

- за `.widget` лежит `body { background: var(--bg) }` — сплошной `#08404d`.
  `.stage` своего фона не имеет, ничего между ними нет. Размытие константы даёт
  ту же константу;
- за `.chips` лежит собственная плашка виджета `rgba(0, 0, 0, 0.6)` — тоже
  сплошная.

Два исключения, где под размытием действительно есть картинка и его надо
сохранить:

- `.widget[data-chips-overlay] .widget-body > .chips` — чипы карты висят над
  растровой подложкой;
- вся стеклянная хрома дока (`.dock-btn`, `.nav-pill`, `.nav-scene-option`),
  `.map-hud`, `.map-credit`, `.ax-tooltip`, `.splash-cta`, `.lang--splash`,
  `.settings-panel`, `.shell-toast` — они лежат поверх бордов и растра.

**Действие [V]:** снять `backdrop-filter` с `.widget` и с базового `.chips`,
вернуть его точечно только на оверлейные чипы карты. 39 слоёв → 4–5.
Единственный кадр, где разница теоретически видна, — перетаскивание виджета
поверх соседа (`[data-moving]` поднимает его на `z-index: 40`); если это
окажется заметно, размытие возвращается одним правилом
`[data-grid-item][data-moving] .widget`.

Проверяется пиксельным диффом (шаг 0) и трассировкой Performance на
конференционной машине — там это GPU-бюджет, а не абстракция.

### C2. Две пары одинаковых flex-обёрток **[V]**

- `.widget-view` и `.widget-view-mount` — идентичные блоки. Первый мёртв

- `.ax-chart-shell` и `.ax-chart` — идентичные `flex: 1; column; min-*: 0`.
  Различаются только когда есть подпись или боковая легенда. Схлопывать можно,
  но выигрыш — один узел на график, а риск ненулевой: **низкий приоритет**.

### C3. Механика «скользящей пилюли» написана дважды **[0]**

`board.js:112 attachChipTabs` (для `.chips`) и `shell.js:333 snapNavPill` /
`glideNavPill` (для `.nav`) — это один и тот же конечный автомат
ghost → bloom → settle, с одними и теми же токенами `--chip-dur-*`, набранный
двумя разными руками. В CSS та же пара: `.chip-pill` (`widget.css:254`) и
`.nav-pill` (`shell.css:198`) повторяют один и тот же блок `transition`.

Выносится в один хелпер `Pill.attach(track, items, opts)`; `.nav` от `.chips`
отличается только тем, что у него нет drag-жеста и свои значения `--chip-fill`
(они и так переопределены локально в `.dock`).

### C4. Хайрлайн шапки: объявлен один раз, снят четырьмя правилами **[0]**

`.widget-head { border-bottom }` затем гасится в
`.widget[data-chart='indicator']`, `.widget[data-chart='map']`,
`.widget[data-chips-row]` и — отдельной строкой — `[data-grid-item='eco-mon']`.
Последнее это ID конкретного виджета борда Ecosystem, зашитый в общий
`widget.css`: ровно тот вид долга, ради которого затевается уборка.

Инвертировать: линия по опт-ину (`.widget[data-rule] .widget-head`), флаг

исчезают, `eco-mon` объявляет себя в `ecosystem.js`, где ему и место.

## D. Layout thrash в ResizeObserver **[0]**

`board.js:555 reserveTabsWidth` внутри колбэка `headObserver` для каждой записи
делает **чтение → запись → чтение → запись**:

```
chipsEl.offsetWidth          // read  — форсирует layout
title.style.paddingRight = …  // write — инвалидирует его обратно
chipsEl._tabs.snap()          // read (getBoundingClientRect) + write
```

На семи виджетах это семь синхронных layout-ов за один ресайз, на KPI Library —
двадцать. Лечится расщеплением цикла: сначала собрать все `offsetWidth` и
прямоугольники, потом одним проходом записать.

Есть и вариант без JS вообще — держать `.chips` в потоке шапки со
сдвигом `margin: -4px -4px 0 0` вместо `position: absolute; top/right: 8px`,
тогда заголовок ужимается сам и `reserveTabsWidth` не нужен. **Но** это меняет
высоту шапки (чипы 32px против `min-height: 16px` у заголовка) и ломает
намеренную развязку «чипы не плывут за высотой заголовка», описанную в
комментарии `widget.css:60`. Оставляю как опцию с пометкой **[V]**, не как
рекомендацию.

## E. Найденный баг вёрстки — нужно решение **[!]**

`shell.css:622` объявляет `.ticker-item b`, то есть элемент `<b>`. Тикер такого
элемента не выдаёт: `shell.js:663` печатает `<span class="b">`, `class="g"`,
`class="y"`. Правила для `.g` и `.y` есть (`shell.css:628`, `634`), для `.b` —
нет.

Следствие: каждое «синее» число в бегущей строке остаётся `--mut` вместо `--cy`
и не получает `tabular-nums`. На скриншоте это видно прямо: `93.1%` зелёное, а
`21 405`, `402` и `265 000` — серые, хотя задумывались голубыми.

Это единственная правка из всего плана, которая **меняет картинку**. Варианты:

1. починить (`.ticker-item b` → `.ticker-item .b`) — четыре числа станут
   голубыми, как задумано;
2. узаконить нынешний вид — удалить мёртвое правило, а `.g`/`.y` оставить.

Нужно решение до начала работ, иначе пиксельный дифф на шаге 0 будет шуметь.

### Где я ошибся в диагнозе, и что из этого вышло

Пункт A утверждал, что `backdrop-filter` за карточкой можно просто снять:
размытие плоского фона возвращает тот же цвет. Арифметика верна, вывод — нет.
**Любой** `backdrop-filter` поднимает карточку на собственный композиторский
слой, а Chrome растрирует текст, SVG и скруглённые углы на слое иначе, чем в
основном растре. Снятие свойства сдвинуло ~6% пикселей на каждом борде и 17% на
Big Screen — сплошное сглаживание, ничего осмысленного. Плюс док, у которого
своё размытие, стал брать другой backdrop.

Решение — оставить слой и убрать только гауссиану: `blur(0px)` вместо
`blur(256px)`. Слой и его растеризация сохраняются ровно, работа компоситора —
нет. Гауссиан на KPI Library: **39 → 19**, и ушли именно карточные, самые
дорогие по площади (карточка ~560×230 против трека чипов ~100×32).

## Решения приняты

### A. Бегущая строка — починено (шаг 5) ✅

`shell.css` объявлял `.ticker-item b` — элемент `<b>`, которого тикер не
печатает: разметка выдаёт `<span class="b">`. Правила для `.g` и `.y` работали,
для `.b` — нет, поэтому каждое «голубое» число молча падало на `--mut` и теряло
моноширинные цифры.

Три тона теперь объявлены одним списком, и цвет у каждого свой. Проверено:
изменились ровно 805 пикселей на кадр, все в полосе тикера (y 26–45), заставка
не тронута; `402`, `21 405` и `265 000` стали голубыми, подписи рядом остались
приглушёнными.

### B. Наложение заголовка на чипы в KPI Library — оставлено как есть

Библиотека собирает карточки через `Board.widgetMarkup`, но проход,
резервирующий в заголовке место под чипы, живёт в `mountScene`, куда
custom-render-борд не заходит. Ни одна карточка библиотеки этот отступ не
резервирует — ни в одной локале. По-английски заголовки короткие и это сходит с
рук; по-арабски они заезжают под трек чипов, а фон трека
(`rgba(38, 38, 38, 0)`) полностью прозрачный, так что видно это только потому,
что 410-пиксельная гауссиана размазывает наложение в муть.

Решено не трогать: на стенде этого никто не видел, а починка меняет вид
арабского борда. Записано на месте, в комментарии к `.chips` в `widget.css`.

Цена решения: `.chips` не может уйти в `blur(0px)`, потому что там размытие —
не украшение, а заливка. Это **16 гауссиан** на борде библиотеки, которые
снялись бы следом за починкой отступа. Единственный оставшийся резерв.

## Чего в плане намеренно нет

- **Минификации CSS/JS в `bundle.mjs`.** Файл открывается с флешки, 1.5 МБ
  локально грузятся мгновенно, а комментарии в нём — это и есть документация
  порта Axion. Экономия байт здесь ничего не покупает.
- **Слияния 11 стилей в один файл.** В бандле они и так инлайнятся, а в
  исходнике разделение по слоям (`tokens → base → grid → widget → chart-dsl →
  map → library → tooltip → motion → shell → splash`) — это порядок каскада,
  который сейчас читается с первого взгляда.
- **Правок в `Dashboards/*.html`.** Это архив исходного клиентского
  деливерабла, эталон для сверки, а не работающий код.
- **Тюнинга `container-type: size`** (51 контейнер на KPI Library). Каждый из
  них несёт реальный `cqh`-кап, ради которого и заведён; изоляция размера,
  которую он даёт, скорее помогает layout-у, чем вредит.
